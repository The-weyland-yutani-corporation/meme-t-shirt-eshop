# Support and ownership

This repository is a reference demonstration, not a managed commerce service.
No support SLA, production on-call coverage, or maintainer response time is
promised. Agree a named owner and escalation route before a workshop or pilot.

## Getting help

1. Follow [setup](docs/setup.md) and [demo reset/fallback](docs/demo.md).
2. Check [architecture boundaries](docs/architecture.md) and
   [open readiness gates](docs/readiness.md) before treating a limitation as an
   implemented integration.
3. For a non-sensitive reproducible bug, use the repository's issue tracker if
   available and permitted by its owners. Include commit, Node/npm versions,
   exact command or synthetic steps, expected/actual result, and sanitized logs.
   Do not include `.env` contents, credentials, customer data, or private URLs.
4. Use [private security reporting](SECURITY.md) for vulnerabilities or exposed
   secrets, not a public issue.

Azure identity, billing, deployment approvals, and teardown belong to the
designated subscription/repository operator. Provider account questions belong
to the account owner; this project does not supply Stripe or Printful service
support. Catalog access/schema questions require an authorized Catalog owner.

Before handoff, record the pilot sponsor, technical owner, workshop facilitator,
security contact, cost owner, and agreed support window in your approved internal
charter. Do not publish personal contact information without consent.
